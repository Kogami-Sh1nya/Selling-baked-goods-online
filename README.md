# Bakery Street — онлайн-продажа выпечки

Полноценный учебный репозиторий сайта интернет-магазина выпечки с REST API, PostgreSQL, Express.js, React, Node.js, JWT-авторизацией и HTTPS.

Проект реализует каталог выпечки, корзину, оформление заказа, тестовую оплату, личный кабинет, историю заказов, отзывы, панель продавца и административную панель.

---

## Использованный стек

**Frontend:** React + Vite + React Router.

React используется для построения компонентного интерфейса: карточки товаров, модальные окна, корзина, профиль, формы авторизации и панель управления вынесены в отдельные логические части. Vite используется как современный инструмент сборки и локального запуска. React Router отвечает за маршрутизацию между страницами.

**Backend:** Node.js + Express.js.

Node.js используется как серверная платформа. Express.js реализует REST API, middleware, маршруты, авторизацию, разграничение доступа по ролям и обработку запросов от клиента.

**База данных:** PostgreSQL.

PostgreSQL используется для хранения пользователей, ролей, категорий, товаров, заказов, позиций заказа, отзывов и тестовых платежей. База данных подходит для проекта, потому что поддерживает связи между таблицами, внешние ключи, ограничения и транзакции.

**Авторизация:** JWT.

JWT используется для авторизации пользователей и проверки защищённых маршрутов. После успешного входа сервер выдаёт токен, который клиент отправляет в заголовке `Authorization`.

**HTTPS:** локальный самоподписанный сертификат.

Frontend и backend работают по HTTPS. Для локальной разработки используются файлы сертификата `key.pem` и `cert.pem`.

## Аналоги и отличия

### React

Аналоги: Vue.js, Angular.

Vue проще для небольших проектов и быстрее осваивается. Angular предоставляет более строгую архитектуру, но требует больше кода и подходит для крупных корпоративных систем. React выбран как гибкий и популярный вариант для SPA-приложения.

### Vite

Аналоги: Create React App, Webpack.

Create React App проще для старта, но медленнее и считается менее современным вариантом. Webpack гибкий, но требует больше настройки. Vite быстрее запускает проект и удобен для разработки React-приложений.

### Express.js

Аналоги: NestJS, Fastify.

NestJS удобен для крупных backend-приложений со строгой архитектурой и модулями. Fastify быстрее по производительности. Express выбран из-за простоты, понятности и удобства для учебного REST API.

### PostgreSQL

Аналоги: MySQL, MongoDB.

MySQL тоже является реляционной СУБД, но PostgreSQL удобнее для сложных связей, ограничений и транзакций. MongoDB хранит документы и хуже подходит для проекта, где важны связи между пользователями, заказами, товарами и позициями заказа.

### JWT

Аналоги: серверные сессии.

Сессии хранят состояние авторизации на сервере. JWT удобнее для REST API, потому что клиент хранит токен и отправляет его с запросами.

## Основные сущности базы данных

В проекте используются таблицы:

- `users` — пользователи и роли;
- `categories` — категории товаров;
- `products` — товары, цены, остатки, изображения, состав;
- `orders` — заказы пользователей;
- `order_items` — состав заказа;
- `payments` — тестовые платежи;
- `reviews` — отзывы к товарам.

## REST API

Все маршруты backend начинаются с `/api`.

### Авторизация

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| POST | `/api/auth/register` | гость | регистрация пользователя |
| POST | `/api/auth/login` | гость | авторизация пользователя |

---

### Категории

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/categories` | все | получить список категорий |

---

### Товары

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/products` | все | получить список товаров |
| GET | `/api/products/:id` | все | получить один товар |
| POST | `/api/products` | seller, admin | добавить товар |
| PATCH | `/api/products/:id` | seller, admin | изменить товар |
| DELETE | `/api/products/:id` | admin | удалить товар |

---

### Изображения товаров

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| POST | `/api/uploads/products` | seller, admin | загрузить изображение товара |

Загруженное изображение сохраняется в `server/uploads/products`, а в базу данных записывается путь к изображению.

---

### Заказы

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| POST | `/api/orders` | user, seller, admin | оформить заказ |
| GET | `/api/orders/my` | авторизованный пользователь | получить историю своих заказов |
| GET | `/api/orders` | seller, admin | получить все заказы |
| PATCH | `/api/orders/:id/status` | seller, admin | изменить статус заказа |

Статусы заказов:

- `новый`;
- `готовится`;
- `в доставке`;
- `доставлен`;
- `отменён`.

Если заказ получает статус `отменён`, товары из заказа возвращаются на склад.

---

### Отзывы

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/products/:productId/reviews` | все | получить отзывы товара |
| POST | `/api/products/:productId/reviews` | авторизованный пользователь | добавить отзыв |
| GET | `/api/reviews` | admin | получить все отзывы |
| DELETE | `/api/reviews/:id` | admin | удалить отзыв |

---

### Пользователи

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/users` | admin | получить список пользователей |
| PATCH | `/api/users/:id/role` | admin | изменить роль пользователя |
| DELETE | `/api/users/:id` | admin | удалить пользователя |

## Установка и запуск

### 1. Требования

Необходимо установить:

- Node.js 20 или выше;
- PostgreSQL 14 или выше;
- OpenSSL;
- npm.

---

### 2. Создать базу данных

```bash
createdb baking
```

Или через psql:

```sql
CREATE DATABASE baking;
```

---

### 3. Настроить переменные окружения

В папке `server` создайте файл `.env`.

Пример:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=baking
DB_USER=postgres
DB_PASSWORD=ВАШ_ПАРОЛЬ_POSTGRESQL

HTTPS_PORT=5000
CLIENT_URL=https://localhost:5173

JWT_SECRET=Ваш секретный ключ
```

Описание:

- `DB_HOST` — адрес PostgreSQL;
- `DB_PORT` — порт PostgreSQL;
- `DB_NAME` — имя базы данных;
- `DB_USER` — пользователь PostgreSQL;
- `DB_PASSWORD` — пароль PostgreSQL;
- `HTTPS_PORT` — порт backend-сервера;
- `CLIENT_URL` — адрес frontend-приложения;
- `JWT_SECRET` — секретная строка для подписи JWT.

`JWT_SECRET` не нужно получать из внешнего сервиса. Это любая длинная строка, которую задаёт разработчик.

---

### 4. Установить зависимости

Из корня проекта:

```bash
npm install
```

Затем отдельно для backend:

```bash
cd server
npm install
```

И для frontend:

```bash
cd ../client
npm install
```

Вернуться в корень:

```bash
cd ..
```

---

### 5. Создать HTTPS-сертификаты

Сертификаты должны находиться в папке:

```text
server/certs
```

Нужные файлы:

```text
server/certs/key.pem
server/certs/cert.pem
```

Создание сертификата:

```bash
mkdir server/certs
openssl req -x509 -newkey rsa:2048 -nodes -keyout server/certs/key.pem -out server/certs/cert.pem -days 365
```

В поле `Common Name` рекомендуется указать:

```text
localhost
```

Для локального учебного проекта браузер может показывать предупреждение о недоверенном сертификате. Это нормально для самоподписанного сертификата.

---

### 6. Применить SQL-код базы данных

Из папки `server`:

```bash
psql -U postgres -d baking -f database/schema.sql
psql -U postgres -d baking -f database/seed.sql
```

Если на Windows возникает проблема с кодировкой, можно перед импортом выполнить:

```powershell
$env:PGCLIENTENCODING="UTF8"
chcp 65001
```

---

### 7. Запустить проект

Из корня проекта:

```bash
npm run dev
```

Адреса:

```text
Frontend: https://localhost:5173
Backend:  https://localhost:5000
Health:   https://localhost:5000/api/health
```

Пароль для всех тестовых аккаунтов:

```text
123456789
```

Роли:

- `admin@bakery.local` — администратор;
- `seller@bakery.local` — продавец;
- `user@bakery.local` — обычный пользователь.

## Тестовая платёжная система

Платёжная система учебная и не подключена к реальным банкам.

Она используется только для проверки оформления заказа.

При оформлении пользователь вводит:

- номер карты;
- имя владельца карты;

Номер карты должен состоять из 16 цифр.

Пример тестовой карты:

```text
4111111111111111
```

После оформления заказа:

1. Backend проверяет данные заказа.
2. Создаётся запись в таблице `payments`.
3. Создаётся запись в таблице `orders`.
4. Создаются позиции заказа в таблице `order_items`.
5. Количество товара уменьшается на складе.
6. Пользователь видит заказ в истории профиля.

Платёж получает статус:

```text
paid
```

Заказ получает начальный статус:

```text
новый
```

## Проверка функционала

1. Открыть главную страницу.
2. Проверить каталог товаров.
3. Проверить выпадающий список категорий в верхнем меню.
4. Открыть расширенную карточку товара.
5. Добавить товар в корзину.
6. Убедиться, что нельзя добавить больше товара, чем есть в наличии.
7. Перейти в корзину.
8. Заполнить данные доставки.
9. Ввести тестовые платёжные данные.
10. Оформить заказ.
11. Открыть профиль и проверить историю заказов.
12. Оставить отзыв к товару.
13. Войти как продавец.
14. Проверить управление товарами и заказами.
15. Войти как администратор.
16. Проверить управление пользователями и отзывами.

---

## Особенности работы склада

При оформлении заказа количество товара уменьшается.

Если заказ отменяется, количество товара возвращается на склад.

Если товар установлен как «не в наличии», его количество становится `0`.
